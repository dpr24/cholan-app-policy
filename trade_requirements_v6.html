1. Project Overview

The app is an automated trading engine focused on NIFTY options trading. Main responsibilities: - ingest market/candle data, evaluate multi-timeframe signals, - select contracts, size positions based on risk profile, - place/modify/cancel orders via Angel broker API, - persist trades and events in DB for audit.

2. Architecture & Key Components

  • Entry point: src/app.js, src/server.js (HTTP + websocket endpoints).
  • Execution: src/execution/order.manager.js, src/execution/order.service.js, src/execution/position.manager.js.
  • Risk: src/risk/capital.manager.js, src/risk/trade.limits.js, src/risk/cooldown.manager.js, src/risk/gap.guard.js.
  • Strategy V2 orchestrator and rules under src/strategy/v2/ (orchestrator, timeRules, pullbackRules, entryChecklist, exitRules).
  • Indicators: src/indicators/ — MACD, Pullback, CandleFilter, Volume.
  • Data persistence: Sequelize models in src/models/ (orders, trades, events).

3. Broker Integration & Order Payloads

Broker glue lives in src/broker/angelClient.js and src/execution/order.service.js. The OrderService resolves instruments and builds place/modify payloads expected by Angel APIs. Important fields:

  • tradingsymbol — instrument mnemonic
  • symboltoken — numeric token optionally used for resolution
  • quantity — integer shares/lot units
  • ordertype — "LIMIT" or "MARKET" (mapped via toOrderType)
  • producttype — e.g. "MIS" mapped via toProductType
  • price, triggerprice, stoploss, squareoff

Order placement logic (high-level)

  1. Resolve instrument (exchange/tradingsymbol/symboltoken) — resolveInstrument().
  2. Build payload via buildPlaceOrderPayload() and call angelClient.placeOrder().
  3. On errors, OrderManager retries up to config.MAX_ORDER_RETRY with delay ORDER_TIMEOUT/2.

4. Execution Flow (Order lifecycle)

Primary flow is implemented in src/execution/order.manager.js:

  • validateOrder(config) — validates trading symbol, quantity bounds, price > 0. Checks risk-reward when stopLoss/target both provided: reward/risk = |target - price| / |price - stopLoss| must be ≥ STRATEGY_MIN_PROFIT_RATIO.
  • Compares configured price against market LTP and enforces PRICE_SLIPPAGE_PERCENT.
  • placeEntryOrder(config) — validates, attempts to place LIMIT entry as BUY with configured quantity and entryPrice. Stores metadata in activeOrders map and maintains orderEvents for audit trail.
  • placeMarketOrder(config) — used for exits; places MARKET order payload (price: 0).
  • modifyStopLoss/modifyTarget(cancel) — wrapper that calls OrderService.modifyOrder/cancelOrder and updates in-memory order meta and logs events.

5. Position & Exposure Calculations

Position processing

PositionManager.processPositions() normalizes broker position payloads to: { symbol, quantity, averagePrice, currentPrice, pnl, pnlPercent }. PnL percent computed as:

pnlPercent = avg > 0 ? (pnl / (|quantity| * avg)) * 100 : 0

Exposure

Total exposure computed as:

totalExposure = Σ(position.quantity * position.averagePrice)

CapitalManager stores exposure per day in Redis at key exposure:YYYY-MM-DD.

6. Risk Management

Main logic is in src/risk/capital.manager.js. Key concepts:

  • Risk profile built from Redis key ACTIVE_RISK_PROFILE or defaults from src/config/risk.profiles.js. Profile fields include capitalSize, perTradeRiskPercent, perTradeRiskValue, maxCapitalUtilizationPercent, lotSize, etc.
  • Max capital: maxCapital = capitalSize * maxCapitalUtilizationPercent / 100
  • Sizing percent: sizingPercent = dashboard per-trade percent if present else profile percent
  • Percent risk capital: percentRiskCapital = capitalSize * sizingPercent / 100
  • tradeCapital: capped to min(maxCapital, perTradeRiskValue || percentRiskCapital)

Position sizing formulas

Two sizing methods are used across code:

  1. Simplified per-share size (from utils.calculatePositionSize): 
    riskAmount = (capital * riskPercent) / 100
pricePerShare = |entryPrice - stopLoss|
qty = floor(riskAmount / pricePerShare)
  2. Lot-based sizing (CapitalManager): 
    minCapitalFor1Lot = entryPrice * lotSize
rawLots = tradeCapital / minCapitalFor1Lot
lots = floor(rawLots) (ensure at least 1 if tradeCapital >= minCapitalFor1Lot)
qty = lots * lotSize
totalCost = qty * entryPrice

Trade eligibility checks

CapitalManager.canTrade() checks Redis counters and limits: - open_positions_count <= profile.maxPositions - daily trade count < MAX_TRADES_PER_DAY - trend trade count < MAX_TRADES_PER_TREND

Cooldowns & consecutive losses

CooldownManager tracks consecutive losses per day (Redis key losses:YYYY-MM-DD), and when limit reached, activates cooldown:active for 5 trading days. Cooldown end computed by skipping weekends and setting end timestamp to 15:30 of final trading day.

7. Strategy V2 — Orchestration & Decision Flow

Files in src/strategy/v2/ form the entry decision pipeline. Key steps:

  1. Market & time gates — market open and EntryTimeGate boundaries (default 09:45–14:45 IST).
  2. MACD 1H crossover detection (pullbackRules) — uses standard MACD (12,26,9) via technicalindicators. A bullish crossover is histogram negative→positive with MACD line crossing above signal line.
  3. Multi-timeframe alignment — validate lower TF (15m/30m) alignment with the 1h bias.
  4. Contract selection — selectContract() chooses option leg(s) from options chain with constraints such as minimum premium, ITM points, days-to-expiry, strike window, last 3-days premium checks, and greeks snapshot when available.
  5. CrossPrice anchor + tolerance — on initial crossover the system stores a crossPrice (index snapshot). Entry only allowed while live index remains within CrossPrice ± tolerance (config CROSSPRICE_INDEX_TOLERANCE_POINTS).
  6. Entry checklist — all gates combined via evaluateEntryChecklist(). Any failed gate blocks entry and returns human-readable reason(s).

After entry

After an entry is confirmed, afterEntryConfirmed locks bias, increments trade counts, and updates state via src/strategy/v2/tradeState.js. Exit evaluation uses exitRules including partial book profit rules and full exit conditions.

8. Indicators & Exact Calculations

MACD

Implemented in src/indicators/macd.indicator.js with params: fast=12, slow=26, signal=9. The library returns arrays of {MACD, signal, histogram}. A crossover detection checks histogram sign changes and MACD vs signal relationships. findLastCrossover maps result index back to candle index (accounting for result length shorter than candles).

Pullback calculation

Utility calculatePullback(high, low, close) returns: 

pullbackPercent = ((close - low) / (high - low)) * 100
Zig-zag levels (config ZIGZAG_LEVELS) used: 1st ≥70%, 2nd ≥60%, 3rd ≥55%.

Candle filters & pattern checks

  • Consecutive candles: need strict consecutive bullish/bearish counts as configured (e.g., 3).
  • Mixed candle rule (lower TF): last 6 candles cannot be all same color; need at least one opposite to confirm pullback.
  • Doji/Hammer detection thresholds used in CandleFilterIndicator (body/range ratios).
  • Gradual vs gap pullback: reject entries where openPullback > 80% (gap entry) — prefer gradual retracements.

Volume strength

Computed in VolumeIndicator.analyzeVolume(): - avgVolume = average of previous 20 candles - multiplier = currentVolume / avgVolume - strength: <1.5 = WEAK, 1.5–2.0 = GOOD, ≥2.0 = STRONG

9. Utilities & Helper Functions

Located in src/utils/. Notable functions (formulas):

  • calculatePercentage(current, previous) = ((current - previous) / previous) * 100
  • calculateTrailingStop(entryPrice, currentPrice, trailingPercent) returns max(entryPrice,currentPrice) * (1 - trailingPercent/100)
  • calculateRisk(entryPrice, stopLoss, quantity) = |entryPrice - stopLoss| * quantity
  • calculateReward(exitPrice, entryPrice, quantity) = |exitPrice - entryPrice| * quantity
  • linearRegression(points) returns slope, intercept, rSquared (least-squares)

10. Redis Keys, Counters & Side Effects

  • exposure:YYYY-MM-DD — daily exposure amount (CapitalManager).
  • trades:daily:YYYY-MM-DD, trades:weekly:YYYY-MM-DD, trades:monthly:YYYY-MM — counters for TradeLimits.
  • open_positions_count — number of currently open positions (used by CapitalManager.canTrade()).
  • losses:YYYY-MM-DD and cooldown:active — tracked by CooldownManager.
  • ACTIVE_RISK_PROFILE — JSON risk profile override used by CapitalManager.
  • crossPrice:{CALL|PUT} — stored cross-price anchor and metadata (strategy state).
